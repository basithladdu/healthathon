## Top findings for Sahara

1. **cdci is the most useful repo in this lane.** It is a free Indian drug and lab code dataset with an India-only redistribution licence, and palliative medicines are included. Use https://github.com/ohcnetwork/cdci/tree/HEAD/data/source (GenericMaster.txt, BrandMaster.txt, and `clci/` for lab codes) to power Sahara's medicine picker offline. Attribution is required; see DATA_LICENSE.md and NOTICE in the repo. No API or permission is needed.
2. **CARE already has a patient/family OTP login path.** care_zoom_be uses `JWTTokenPatientAuthentication` with `OTPAuthenticatedPermission` (`care_zoom/views.py` around lines 236-259), and family members follow CARE's shared-phone access. That is the sanctioned way for a family app to read a patient's own data, but only on a hospital's CARE deployment.
3. **Family video visits have a ready pattern** in care_zoom_be and care_zoom_fe: a schedule set to video mode, a patient portal panel, and a passcode link that works without login. The design is in care_zoom_be/IMPLEMENTATION.md.
4. **Custom questionnaire question types are possible.** care_vision_prescription_fe `src/manifest.tsx` (`registeredQuestionGroups`) is the template for a pain or symptom-score question group inside CARE.
5. **care_spec** (input/resources, input/pagecontent/mapping.md) is the reference for mapping Sahara data to CARE/FHIR R5. Its README claims MIT but there is no LICENSE file, so ask OHC before copying.
6. **ccm_uhi has no-login endpoints, including a patient-data lookup.** It exposes practitioner and slot listings, and returns a patient's name, phone, date of birth and address to anyone holding a booking ID. It only works where a hospital has installed the plugin. Treat this as a privacy issue to report to OHC, not a data source. Its notification jobs (ccm_uhi/README.md, "Notifications" section) are a good model for Sahara reminders.
7. **No public data API was found in this lane.** OHC's Metabase (care_tools) needs credentials. Every live CARE endpoint needs a hospital deployment plus staff JWT, patient OTP or a per-appointment secret.
8. **Licences to confirm with OHC:** careui, care_spec, care_tools, care_serial_scanner_fe, care_system_diagnostics_fe and care_vision_prescription_fe have no LICENSE file (some declare MIT only in package.json or the README). commission is AGPL-3.0 and should be avoided.

I did not check the `care` backend for unauthenticated endpoints; it is not in this lane's list.

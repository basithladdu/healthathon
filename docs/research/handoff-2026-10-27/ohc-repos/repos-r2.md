## Top findings for Sahara

1. **No bulk patient data is reachable without a hospital's permission.** The no-auth surface in care_fe is OTP send/login and password-reset OTP. Patient data needs either the patient-OTP token (only that patient's own record and appointments, on one hospital's instance) or a staff JWT or service-account token. Public facility listing (`/api/v1/getallfacilities/`) looks unauthenticated; the `care` backend lane should confirm it. (high confidence)
2. **Best route for a family app:** CARE's patient-OTP portal APIs (`/api/v1/otp/*`, `/api/v1/otp/patient/`, `/api/v1/otp/slots/*`). This works against any CARE deployment that enables patient login, with the patient's or family's own phone OTP. Each deployment has its own base URL. Reference: care_fe src/types/otp/otpApi.ts, src/types/scheduling/PublicAppointmentApi.ts, src/types/emr/patient/publicPatientApi.ts.
3. **care_im_wrapper (MIT)** is the most reusable design for caregiver messaging: WhatsApp triggers, a menu bot and tokenized document links. The document-link pattern is good. The phone-plus-year-of-birth login is too weak to copy for palliative records. https://github.com/ohcnetwork/care_im_wrapper (docs/documents.md, docs/usage.md)
4. **Voice-to-form:** care_filly is a thin broker around the commercial Medispeak scribe API, so the transcription itself is not open. Reuse the token-broker pattern, not an engine.
5. **Pain body drawing:** care_excalidraw_fe has no body template; it is a generic canvas. Sahara would need its own body outline (native Android drawing is simpler than embedding Excalidraw).
6. **Reusable as data, MIT:** care_fe Malayalam and other Indian-language locale files (public/locale/ml.json etc.), the questionnaire type set, and the I/O LOINC catalogue (care_io_balance_fe/SCHEMA.md).
7. **care_mcp** only matters if a partner hospital installs it and issues a scoped service account. Its code is on branch `claude/care-mcp-plugin-m9ktd9`, not `develop`.
8. **Licences:** everything is MIT except care_hello_fe (ISC, no LICENSE file). Several MIT repos declare it only in package.json or setup.py with no LICENSE file; reuse is probably fine but worth confirming with OHC. The Filly mascot is OHC branding; ask before using it.

## 1. NEW or CONTRADICTS earlier docs (most important first)

1. **NEW: no staff-side symptom entry outside an active encounter, in the UI too.** "Without an active encounter, the screen shows \"Symptoms cannot be recorded without an active encounter\"." and severity options are only "Mild, Moderate, Severe". (https://docs.ohc.network/flows/clinical/condition/record-symptom) Same for diagnoses: "Diagnosis cannot be recorded without an active encounter". (https://docs.ohc.network/flows/clinical/condition/record-diagnosis) Earlier docs had this at API level (encounter required); this confirms the staff screen, and that a 0-10 score cannot be a symptom severity. Sahara diary symptoms must map to questionnaire responses or be attached to a staff-opened encounter.
2. **NEW: a completed home visit is effectively frozen for good on default settings.** "Your deployment sets how many hours after the last change you can restart a completed encounter. The default is zero hours. With that setting, Care refuses every restart." (https://docs.ohc.network/flows/clinical/encounter/restart-encounter) and "After the encounter closes, nobody can change it. Nobody can record new clinical data on it." (https://docs.ohc.network/flows/clinical/encounter/complete-encounter) Implication for the plugin design in CARE_DEEP_DIVE (staff accept family items "into this encounter"): family items arriving after the visit is completed cannot go into that visit; staff need an open or new encounter.
3. **NEW: per-patient cap on open encounters.** "Patient already has maximum number of active encounters (5) in the facility" ... "The default maximum is 5." (https://docs.ohc.network/flows/clinical/encounter/create-encounter) A plugin that opens an encounter per family submission would hit this; reuse one open home-health encounter instead.
4. **NEW (privacy risk for any "give family a staff account" workaround):** "Every signed-in user can search for and view the basic profile of any other user. Care does not limit the results to the people you work with." (https://docs.ohc.network/flows/access-governance/user/search-for-user) Also care team membership grants access: "Membership of the care team can give a user access to the encounter." (https://docs.ohc.network/flows/clinical/encounter/manage-encounter-care-team) and members must be facility staff: "The person that you add is a user of a department in the facility." (https://docs.ohc.network/flows/clinical/care-team/add-care-team-members) Supports earlier conclusion that family cannot be on a CARE care team, and adds a concrete reason not to hand families staff accounts.
5. **NEW detail on consent verification wording:** "Verification Type: The source of the confirmation: Family for a family member or a representative, or Validation for the patient." and "Care accepts one verification for each user on one consent. A second verification from the same user gives an error." ... "Care removes only a verification that the same user added." (https://docs.ohc.network/flows/clinical/consent/verify-a-consent) Earlier docs had family/validation and verified_by = staff; the one-per-user rule and "or a representative" are new. Confirms (no contradiction) "The current version of Care has no screen for consent verification."
6. **NEW: consent edits are narrow and unguarded.** Edit form changes only Status and Note; "Consent Decision, Category, Consent Given On, Consent Valid From and Consent Valid Until" are not editable, and "Care accepts a change from any status to any other status. Care does not ask you to confirm the change." (https://docs.ohc.network/flows/clinical/consent/update-a-consent) Consent attachments: "Care accepts these file types: jpg, jpeg, png, and pdf." and "Care uploads the files after it saves the consent record." (https://docs.ohc.network/flows/clinical/consent/record-a-consent) So a Sahara goals-of-care PDF fits as a consent supporting document. Consent list search is by attached file name only (https://docs.ohc.network/flows/clinical/consent/view-consents). Re-confirms Comfort Care gap (no change).
7. **NEW palliative-relevant enums:** discharge disposition includes "Hospice" and "Expired" (https://docs.ohc.network/flows/clinical/encounter/discharge-patient); encounter tag categories an admin can configure include "Advance Directive", "Contact", "Safety", "Behavioral" (https://docs.ohc.network/flows/clinical/encounter/manage-encounter-tags); location forms include "Room, Bed, Cabinet and House" and "Virtual" (https://docs.ohc.network/flows/clinical/encounter/assign-encounter-location). A deployment could tag home-health encounters with an Advance Directive tag; Sahara export could carry a matching tag label. (Unverified whether any deployment configures such tags.)
8. **NEW: files are never deleted, only archived with a reason, irreversibly.** "Care has no permanent delete for files. Archiving is the only way to remove a file from the active list." "Archiving is irreversible." The archived view "shows who archived the file, when, and why." (https://docs.ohc.network/flows/clinical/files/archive-a-file) "Download is available to every user who can view the file." (https://docs.ohc.network/flows/clinical/files/download-a-file) Relevant to any family upload: once in CARE, a family can't withdraw a file; staff can only archive it. Matters for Sahara's consent/withdrawal copy.
9. **NEW: condition records are append-only.** "Care never deletes a saved clinical record. Care keeps the record and sets its Verification to Entered in Error" (https://docs.ohc.network/flows/clinical/condition/condition-entered-in-error); "You cannot change the Onset Date of a saved record" and "You cannot change the clinical term of a saved record." (https://docs.ohc.network/flows/clinical/condition/update-condition) Clinical history shows "who reported it" (https://docs.ohc.network/flows/clinical/condition/view-clinical-history), which is staff, consistent with earlier docs.
10. **NEW: Volunteer role reads billing and lab reports.** "Can Read Account ... Facility Admin, Administrator, Admin, Staff, Doctor, Nurse, Volunteer, and Pharmacist" (https://docs.ohc.network/flows/billing/account/view-account); same for invoices, payments and "Can Read Diagnostic Report" (https://docs.ohc.network/flows/clinical/diagnostic-report/view-a-diagnostic-report). Relevant to Kerala palliative volunteer model; volunteers are staff accounts, not family.
11. **NEW staff auth facts (not patient/family auth):** self-service TOTP 2FA with backup codes, "An administrator cannot turn it on for another person" (https://docs.ohc.network/flows/access-governance/user/turn-on-two-factor-authentication); "Care has no option for an administrator to reset the password of another user"; forgotten-password reset by email link or "Reset using phone number" OTP (https://docs.ohc.network/flows/access-governance/user/change-password); only a superuser can deactivate, and "Care has no option in the interface to reactivate an archived account" (https://docs.ohc.network/flows/access-governance/user/deactivate-user-account). Create-user requires email, phone and gender (https://docs.ohc.network/flows/access-governance/user/create-user).
12. **NEW: terminology is deployment-configurable.** Symptom/diagnosis/allergy search uses "a standard SNOMED CT ... terminology" and "Your administrator sets the clinical terminology for your deployment." Care team roles "come from a clinical terminology set. The roles can differ between deployments." (https://docs.ohc.network/flows/clinical/allergy-intolerance/record-allergy; https://docs.ohc.network/flows/clinical/care-team/add-care-team-members) So Sahara's export should not hard-code a role or symptom code list as "CARE's".
13. **Minor/billing (low relevance):** one active open billing account per patient per facility; payments methods "Cash, Credit Card, Credit Account, Check, Direct Deposit or Debit Card" (no UPI listed); issuer "Patient or Insurer" (https://docs.ohc.network/flows/billing/payment-reconciliation/record-payment). Re-confirms earlier note that "patient accounts" = billing, not patient login.

Nothing in this slice contradicts the four earlier docs.
